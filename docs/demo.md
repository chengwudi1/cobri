# Cobri 演示

Cobri 是一个 GrokBot 风格的工作助理团队 demo，基于 [Rakazo](https://github.com/elie222/rakazo) 构建。Rakazo 以 Apache-2.0 许可开源，本仓库保留其 `LICENSE` 与版权声明，并在其上增加了演示用的假服务、评测执行器和一键启动脚本。文中所有公司、人物与数据均为虚构。

## 四个 Bot

| Bot | 职责 |
| --- | --- |
| 总管 | 拆解请求，在群聊里分派与汇总；未被点名时不插话。 |
| 研究 | 查竞品官网与行业动态，产出带来源的结论。 |
| 收件箱 | 处理邮件、客户门户会话，准备对外发送的材料。 |
| 日程 | 查冲突、排会议、创建日历事件。 |

## 六条演示主线

1. **群聊路由**：在一个群里同时 @ 两个 Bot，各自独立回复；没被 @ 的总管保持安静。
2. **交接**：一个 Bot 把任务交给另一个 Bot，交接消息在群里可见，由接收方继续执行。
3. **独立电脑速报**：每个 Bot 有自己的电脑与 home，各自取资料并回报，不依赖共享目录。
4. **日历审批**：涉及外部写操作（创建日历事件）时暂停等待人工审批，批准后继续执行。
5. **CRM + 邮件审批**：读取 CRM 联系人与备注、生成邮件草稿，发送前必须经过审批。
6. **竞品监控**：定时任务监控竞品价格与更新日志，有变化时发一条消息，无变化不打扰。

## 本地运行

需要 Node 24.15+ 与 pnpm 9.x；演示脚本会先检查版本。

- 一键启停：`node scripts/cobri-demo.mjs start`，查看状态用 `status`，收尾用 `stop`。`start` 会先探活，已在运行的服务不会被重复拉起；`stop` 只结束由脚本记录的进程，不会影响其他项目。
- 假服务：`demo-fixtures/` 提供五个零依赖的本地服务，默认监听 `0.0.0.0`：
  - 竞品站 `4310`、客户门户 `4311`、假 Gmail `4312`、假日历 `4313`、假 CRM `4314`。
  - 每个服务都提供 `GET /__state` 与 `POST /__reset`，部分服务提供 `/openapi.json`，可直接作为 Rakazo 连接器的数据源。
  - Bot 跑在容器里时，通过 `host.docker.internal` 访问宿主上的假服务。
  - 也可以单独启动某个服务，或运行 `node demo-fixtures/start.js` 一次拉起全部。
- 模型：在 Web 端创建账号后，通过连接设置（Connections）接入任意兼容的提供商与模型，不需要厂商专用环境变量。

## 评测

12 条任务定义在 `demo-evals/cases.mjs`，执行器是 `demo-evals/run.mjs`，支持 `--list`、`--dry-run`、`--case <id>`、`--all` 和不需要模型的 `--smoke`。判定只认数据库状态、接口返回、产物文件与连接器记录，Bot 自述不算证据。

- 单条用例重复三次（n=3）：`01/02/04/08/09/11` 为 3/3；`03/06/07/10/12` 为 2/3。
- `05` 为平台阻塞：Bot 消息只能携带文本，不能携带附件。
- 三次全量运行分别通过 8、10、10 条。
- 未配置模型时，相关用例标记为 unqualified，不计为通过。

## 限制

- **Windows 适配**：sandbox supervisor 在 win32 上只放宽目录的 execute 位检查（Node 把 NTFS 目录报成 `0666`，而 Docker Desktop bind mount 对容器 uid 仍可写）。supervisor 的其余 4 个用例在 Windows 上因 symlink/chmod 限制失败，属环境限制。
- **无文件浏览器**：演示不提供浏览 Bot 产物的界面，产物通过接口与日志核对。
- **Bot 消息不带附件**：`message_bot` 只接受 message/intent，附件只挂在发送方线程，接收方无法读取。
